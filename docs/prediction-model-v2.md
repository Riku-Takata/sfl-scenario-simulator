# 勝敗予測モデル v2 設計

対戦カードの勝率、チーム戦のスコア分布、プレイオフ進出確率を、追加データ（start.gg・SFL公式stats・Buckler）を使ってより正確に出すための設計。実装前に方針を合意するための文書。

## 1. 現行モデル（v1）の課題

`src/lib/predictor.ts` の現状と、それぞれの問題点。

| 項目 | 現状 | 問題 |
|---|---|---|
| ボウト勝率 | `0.40×キャラ相性 + 0.35×対キャラ熟練度 + 0.25×(H2H・Elo・HOME補正)` を 22〜82% にクランプ | 重みに根拠がなく、確率として校正されていない。クランプで強弱の差が潰れる |
| 試合形式 | ボウト勝率を直接出している | 先鋒・中堅・延長は**2本先取**、大将は**3本先取**（今季68ボウトで確認）。1ゲームの勝率が同じでも、3本先取のほうが実力差が出やすいのに反映されていない |
| 使用キャラ | 各選手のメインキャラで固定 | サブキャラ起用・HOMEの後出しでのキャラ被せを表現できない |
| 出場選手 | AWAYはElo上位4人を固定順、HOMEは貪欲に被せる | 実際の起用傾向（誰がどのポジションに出やすいか）を使っていない。延長は4人目で固定 |
| 実力値 | 手設定Elo + start.gg + SFL戦績の補正を足し合わせ | 情報源ごとの信頼度が整理されておらず、不確実性を持たない |
| 検証 | なし | 予測が当たっているか（対数損失・Brier・キャリブレーション）を測っていない |

## 2. v2 の全体像

```
選手の実力 θ(選手, キャラ) ──┐
キャラ相性 (公式ダイアグラム) ─┼─► 1ゲーム勝率 ─► ボウト勝率 (2先/3先) ─┐
HOME/AWAY・H2H ──────────────┘                                      │
                                                                     ├─► チーム戦スコア分布 ─► 順位・プレイオフ確率
出場選手モデル (ポジション別起用確率) ──┬──────────────────────────────┤      (モンテカルロ)
使用キャラモデル (キャラ選択確率) ─────┘                                │
                                              不確実性 (θ の事後分布) ─┘
```

### 2.1 1ゲーム勝率（ロジスティックモデル）

```
logit P(A が1ゲーム取る) =
    (θ[A, cA] − θ[B, cB])
  + β_mu   · logit(公式ダイアグラム[cA][cB])
  + β_home · (A が HOME なら +1 / AWAY なら −1)
  + β_h2h  · H2H補正 (少サンプルは0に縮小)
```

- **θ[選手, キャラ] = θ[選手] + δ[選手, キャラ]**
  - `θ[選手]`（総合力）: 次の観測を合わせて推定する（2.2）。
    - start.gg プレミア大会のセット（相手の強さはシードと、SFL選手同士なら相手の θ）
    - SFL公式戦のゲーム結果
    - Buckler のメインキャラ MR（MR差 → 勝率の換算は Elo と同じ式で、ランクマとプロ大会の差を β で調整）
  - `δ[選手, キャラ]`（キャラ別の習熟度）: Buckler の「そのキャラの MR − メインキャラの MR」と、そのキャラの SFL・大会成績。未使用キャラは大きなマイナス（実質的に選ばれない）。
- **キャラ相性**: Capcom公式ダイアグラム（Master帯・月次）。無い組み合わせは現行の事前分布。SFL・start.gg のキャラ登録ゲームでベイズ更新する。

### 2.2 実力値の推定（時系列レーティング）

- Glicko 系の動的レーティングで、`θ` と不確実性 `σ` を持たせる。
- 観測ごとに重みを変える。
  - SFL公式戦 > プレミア大会オフライン > プレミア大会オンライン > ランクマ MR
  - 学習で決める。初期値は 1.0 / 0.8 / 0.6 / 0.3。
- 時間減衰: 古い結果ほど効きを弱める（半減期 120日を初期値に、学習で調整）。
- 不確実性 `σ` は試合数が少ない選手ほど大きく、予測時は事後分布からサンプルする（2.6）。

### 2.3 ゲーム勝率 → ボウト勝率

1ゲーム勝率 `p` から、n本先取の勝率を厳密に計算する。

- 2本先取: `p² (1 + 2q)`、ただし `q = 1 − p`
- 3本先取: `p³ (1 + 3q + 6q²)`

同時に「何対何で決着するか」の分布も出せるので、順位決定に使うバトル差（タイブレーク）もモンテカルロで正しく再現できる。現行は代表値で近似している。

### 2.4 使用キャラモデル

`P(選手が キャラ c を使う | ポジション, HOME/AWAY, 相手キャラ)`

- 事前分布: SFLでの使用実績 + Buckler の直近30日の使用割合（最近増えたキャラを含む）。
- AWAY（先出し）: 事前分布どおりに選ぶ。
- HOME（後出し）: 相手のキャラを見て、勝率が最大になるキャラを高確率で選ぶ（softmax）。どこまで最適に選ぶかの強さは、SFLの実際の被せ行動から学習する。

### 2.5 出場選手モデル

- ポジション（先鋒・中堅・大将・延長）ごとの起用確率を、チーム別の SFL 起用実績から推定する（今季 + 昨季、昨季は減衰）。
- AWAY: 起用確率からラインナップをサンプルする（固定順をやめる）。
- HOME: 相手の先出しを見て、実力値・キャラ相性で最適に近い選手を選ぶ。ここも softmax で、最適化の強さは学習する。
- 同じ選手は同じ試合で1回まで、延長は誰でも出られる、といった SFL のルール制約を入れる。

### 2.6 チーム戦・順位・プレイオフ

- 1試合ごとに「ラインナップ → キャラ → 各ボウトのゲーム結果」をまとめてサンプルし、ポイント・バトル差・ラウンド差まで生成する。
- 残り試合を全部シミュレートし、既存の `simulator.ts` のタイブレーク計算で順位を出す（10,000回）。
- 実力値の不確実性も各シミュレーションでサンプルするので、プレイオフ確率に**幅（例: 62%（55〜69%））**を付けて表示できる。

## 3. 学習と検証

### 3.1 データ

| データ | 件数（目安） | 用途 |
|---|---|---|
| SFL 2025 公式戦（API で取得可） | 60試合・192ボウト・570ゲーム | β・起用・キャラ選択の学習 |
| SFL 2026 公式戦 | 21試合・68ボウト・198ゲーム（第4節時点）、毎節追加 | 時系列での検証 |
| start.gg プレミア大会 | 約4,200セット | θ の推定 |
| Buckler | 蓄積開始後のみ | δ・キャラ選択の事前分布・MR による θ の補助 |

### 3.2 リーク（未来の情報の混入）を防ぐ

- 各試合の予測には、その試合より前の情報だけを使う。
- start.gg・SFL は日付で切れば再現できる。
- Buckler は過去にさかのぼって取れないため、蓄積開始以降の試合でのみ評価する。

### 3.3 評価指標

- ボウト単位の**対数損失**と **Brier スコア**、キャリブレーション（予測 60% の試合が実際に約 60% 勝っているか）。
- チーム戦の勝敗的中率、スコアパターンの対数損失。
- **v1 をベースライン**として同じ試合で比較し、改善した場合だけ切り替える。指標はサイトの「このサイトについて」に公開する。

### 3.4 パラメータ推定

- β・観測重み・減衰半減期・softmax の強さを、SFL 2025 を学習期間として最尤推定する（L2 正則化）。
- 2026 は節ごとにローリングで検証する。
- パラメータは十数個に抑え、少ないサンプルで過学習しないようにする。

## 4.1 実装状況（2026-10-20）

ステップ1・2と、2.1 の単純版（実力差・キャラ相性・HOME）を本番の予測に組み込んだ。詳細は [model-eval-report.md](model-eval-report.md)。

| 検証（SFL 2026、その時点の情報のみ） | 現行 v1 | v2 単純版 |
|---|---|---|
| ボウト 68件 対数損失 / Brier | 0.669 / 0.238 | 0.635 / 0.224 |
| チーム戦 21試合 対数損失 / Brier / 的中率 | 0.668 / 0.238 / 57% | 0.610 / 0.206 / 71% |

- v1 は全ボウトを40〜60%と予測しており、ほとんど情報がなかった。v2 は予測に幅があり、予測した勝率と実際の勝率がおおむね一致する。
- 実力値は start.gg が不可欠。SFL だけで推定すると、予測と実際が逆向きになった（M3）。
- 対キャラ戦績・直接対決は、今のサンプル数ではノイズになり悪化した（M4 < M5）。対キャラ戦績の係数がマイナスになったため外している。Buckler の蓄積が進んだ段階で再評価する。
- 本番の実力値とパラメータは、Step 0 が全履歴から毎回学習し直して `src/data/model-v2.json` に保存する。実力値が無い選手は v1 で計算する。
- **プレイオフ確率は v1 より大きく振れるようになった**（例: ZETA の1位確率 58% → 86%）。v1 がほぼ五分の予測しかしていなかったためで、チーム戦のバックテストでは v2 の方が良い。ただし80%以上と予測した4試合の実際は3勝で、少し強気の可能性がある。節ごとに再検証する。

次の候補: 出場選手モデル（ステップ5。HOME の「必ず最善の被せ」という楽観的な仮定を、実績に基づく確率に置き換える）と、実力値の不確実性（2.6）。どちらも、チーム戦の強気寄りを抑える方向に働く。

## 5. リスクと制約

- **サンプルが少ない**: SFL のボウトはレギュラーシーズンで1シーズン約190件。パラメータを増やしすぎると過学習するので、検証指標で採否を決める。
- **ランクマと大会の差**: MR はランクマの実力で、プロ同士の大会・リーグでの強さとは一致しない。θ への寄与は学習で小さく抑える前提。
- **Buckler の継続性**: 非公開ルートのため止まる可能性がある。Buckler が無くても v2 が動く（該当項を外す）構成にする。
- **キャラ登録の欠損**: start.gg のキャラは1割弱のゲームにしか無い。キャラ別の習熟度 δ は主に Buckler と SFL に依存する。
